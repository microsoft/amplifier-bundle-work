# Work skills

Use the mounted `load_skill` catalog to find a named or relevant skill; load only
needed bodies. Follow its advertised schema and resolve companion resources from
its returned `skill_directory`, not the working directory.

Project skills precede personal skills, then this library. Within each scope,
`.amplifier/skills` precedes `.agents/skills`. Source registration lasts for the
session unless the host explicitly persists it.

Inspect unfamiliar packages before execution. Skills cannot supply missing tools,
credentials, runtimes, permissions, or authority. Check mounted capabilities and
dependencies; report unavailable execution or validation. Preserve the user's
provider and delegation choices. The host owns approvals, history and presentation.

Choose from the user's requested outcome, not just a keyword. A short explanation
or wording edit that mentions a spreadsheet or slide does not need an artifact
workflow. A local workbook and an open live Excel session require different
capabilities. Creating one file from a reference and making a reusable template
skill are different requests. For a revision, retain the prior deliverable unless
the user asks to replace it, recheck the changed content and its rendered views,
and deliver the saved revision.
